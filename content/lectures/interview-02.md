# 双指针与滑动窗口：维护一段合法区间

给定一串字符，要找最长的不重复连续片段。可以枚举起点，再逐个扩展终点；但相邻起点对应的片段大部分重叠，字符计数也会被反复重算。滑动窗口保留这份计数，每次只处理新加入和刚移走的字符。它能够省掉重复工作，前提是已经排除的起点以后也不会变好。

## 先区分三种指针关系

双指针并不是一套统一模板。有序数组两数之和使用两端向中间移动的指针；字符串窗口的左右端点通常同向移动；判断一个字符串是否为另一个的子序列，则是两个指针分别扫描两个序列。代码都有两个下标，正确性理由却各不相同。

对于升序数组 `[1, 3, 4, 8]`，寻找和为 7 的两个数，从首尾开始得到 9，必须减小右端。因为最小的 1 配 8 都已经偏大，其余未排除的值配 8 只会更大，所以 8 可以整体排除。接着 1 + 4 = 5 偏小，同理排除 1，最后得到 3 + 4 = 7。没有排序，这两条排除依据就不成立。

窗口处理的是连续区间，不能随意跳过中间的元素。子序列允许跳过元素，子串和连续子数组不允许。读题时确认这一点，往往能避免选错算法。

## 用不重复片段理解窗口

例子采用字符串 `abba`，目标是找到不含重复字符的最长连续片段。维护闭区间 `[left, right]` 和字符出现次数。右边加入一个字符后，只有这个字符可能造成新的重复；不断移走左边字符，直到它的计数重新变成一。此时窗口内每个字符最多出现一次。

**循环不变量：每轮收缩完成后，当前窗口合法；此前被移走的位置，不可能作为当前右端点的更优合法起点。** 一旦某个旧起点已经包含两次相同字符，继续向右扩展并不能让这次重复消失，因此不必把左指针退回去。

| --- | --- | --- | --- | --- |
| a | a | 无 | a | 1 |
| b | ab | 无 | ab | 2 |
| b | abb | 移走 a，再移走旧 b | b | 2 |
| a | ba | 无 | ba | 2 |

## 实现与总工作量

```python
def longest_unique(text):
    counts = {}
    left = best = 0
    for right, char in enumerate(text):
        counts[char] = counts.get(char, 0) + 1
        while counts[char] > 1:
            old = text[left]
            counts[old] -= 1
            left += 1
        best = max(best, right - left + 1)
    return best
```

虽然有嵌套循环，左右端点各自最多移动 n 次，所以平均时间为 O(n)。字典记录出现过的不同字符，空间为 O(min(n, 字符集合大小))。空字符串自然返回零。如果业务中的“字符”指用户看到的字形而不是 Unicode 码点，需要另行明确分词规则，不能直接把 Python 的一次字符迭代当成所有文本场景的正确单位。

## 什么时候不能直接用窗口

正数数组中，扩大窗口会增大总和，缩小窗口会减小总和，可以据此决定移动方向。如果允许负数，这个性质就不成立。例如移走一个负数反而会增加窗口和，因此“总和太小就只扩张”的策略可能漏解。这时应考虑前缀和、哈希表或其他结构。

例如 `[1,-1,5]` 中寻找和至少为 5 的最短非空区间。如果一直等到总和够大才移动左端，到最后总和为 5，先记录长度 3，再移走 1 得到 4，于是停止收缩；实际最优解却是 `[5]`，长度为 1。中间的 −1 阻止了这套规则继续前进。下面的最短区间代码因此明确要求每个元素为正数。

## 最短窗口：合法时还要继续缩

在正数数组 `[2,3,1,2,4,3]` 中，目标和为 7。固定右端点后，如果当前和已达标，就记录答案并尝试删除左端。删除正数只会减小和，一旦不达标，再删除就更不可能达标。因此当前右端点下的最短合法窗口一定会在这一轮收缩中被检查。

| 右端点 | 加入的值 | 本轮检查到的合法窗口 | 收缩结束后的窗口 | 最短长度 |
| --- | --- | --- | --- | --- |
| 0～2 | 2、3、1 | 无 | `[2,3,1]` | 未找到 |
| 3 | 2 | `[2,3,1,2]` | `[3,1,2]` | 4 |
| 4 | 4 | `[3,1,2,4]`、`[1,2,4]` | `[2,4]` | 3 |
| 5 | 3 | `[2,4,3]`、`[4,3]` | `[3]` | 2 |

```python
def shortest_at_least(values, target):
    # 约定 values 全为正整数，target > 0；无解返回 0。
    left = total = 0
    best = len(values) + 1
    for right, value in enumerate(values):
        total += value
        while total >= target:
            best = min(best, right - left + 1)
            total -= values[left]
            left += 1
    return 0 if best > len(values) else best
```

这里答案在收缩之前更新，因为收缩可能把合法窗口变成非法窗口。前面的最长不重复子串则在收缩完成后更新，因为要先清除重复。两个程序都用 `while`，但更新答案的位置由目标决定，不能只记同一个框架。

每个数加入和移出各至多一次，总时间 O(n)，额外空间 O(1)。`[8]`、目标 7 应返回 1；`[1,2]`、目标 7 应返回 0；空数组也返回 0。若允许目标为零，还要单独约定空区间是否可用，否则这段循环可能移过右端点。

## 不重复窗口也可以跳过一段位置

记录字符最近一次出现的位置，可以直接把左端跳到重复字符的后一位，无须逐个减少计数。不过旧位置可能已经不在窗口里，更新时必须取最大值。

```python
def longest_unique_jump(text):
    last = {}
    left = best = 0
    for right, char in enumerate(text):
        left = max(left, last.get(char, -1) + 1)
        last[char] = right
        best = max(best, right - left + 1)
    return best
```

在 `abba` 中，处理第二个 b 后 left 为 2。接着看到最后一个 a，它的旧位置是 0，早已在窗口外。若直接令 left = 1，就把边界退回去，错误地把 `bba` 当成合法长度 3；取最大值则保持 left 为 2，当前窗口是 `ba`。这个版本平均 O(n) 时间、O(不同字符数) 空间，与计数版本解决同一问题，却依赖不同的状态含义。

## 带重复需求的覆盖窗口

目标字符串若是 `AABC`，窗口必须有两个 A、一个 B、一个 C。只保存字符集合会把 `ABC` 误判为满足。可以维护每种字符的需求量与窗口计数，并记录还有多少种字符没有达标。某字符从需求量减一增加到需求量时，才减少一次未达标种类数；继续增加不会再减少。删除时则在计数从需求量变为需求量减一的那一步恢复未达标状态。

只要所有需求都满足，就尝试收缩，并在移走字符之前保存当前候选。找到区间后再切片返回，避免每次更新答案都复制整段字符串。若每轮都复制一个长度接近 n 的候选，指针移动仍只有 O(n)，复制却可能累积到 O(n²)。

## 从长度改成区间

如果还要返回最长片段本身，可以在 `best` 变大时保存当前 left，最后只做一次 `text[start:start + best]`。相同长度时是否覆盖，决定返回哪一个答案：只在严格变长时更新，就保留最早发现的最长窗口；允许等长覆盖，会偏向后面的窗口。题目若指定返回最靠左的位置，这个小条件也属于正确性的一部分。

对最短区间也一样，先确定长度、再确定并列答案的规则。不要返回移动完成后的 left，因为它可能已经跨过刚记录的最优窗口；应在记录答案的同一时刻保存边界。可以用 `abca` 检查：长度 3 的答案有 `abc` 和 `bca`，保留最靠左的版本应得到 `abc`。

调试时把真实窗口切出来，只用于小输入检查它和维护的状态是否一致。计数版本可以确认字典中每个字符的次数等于切片里的次数；总和版本可以确认 `total` 等于窗口逐项相加的结果。正式大数据运行时移除这类扫描检查，否则每轮验证一个窗口也可能把线性算法变成平方级。

保存区间时统一使用半开区间 `[start,end)`，长度就是 end − start，也与 Python 切片一致；窗口内部若使用闭区间，保存终点时记得加一。
