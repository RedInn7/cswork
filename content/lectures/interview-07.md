# BFS 与拓扑排序：按层传播，按依赖执行

图不一定画成点和线。网页跳转、网格移动、任务依赖，都可以表示为状态和连接。建模时先说清楚边是否有方向、代价是否相同、有没有重复连接和不可达节点。BFS 适合每条边代价相同的最短步数；拓扑排序解决依赖关系中的合法先后顺序。

## BFS：第一次发现就是最短距离

设无向图连接为 A—B、A—C、B—D、C—D。从 A 开始，先发现距离为一的 B、C，再发现距离为二的 D。**队列按距离非递减的顺序处理节点，因此首次发现节点时得到的步数最小。** 这个结论依赖于所有边代价相同，不能直接用于带任意权重的图。

对上面的小图，处理顺序可以是 A、B、C、D；B 和 C 的顺序可以互换，但最短距离不变。

| 取出节点 | 新发现节点 | 队列 |
| --- | --- | --- |
| A | B、C | B、C |
| B | D | C、D |
| C | 无，D 已发现 | D |
| D | 无 | 空 |

下面的动画使用一个独立的网格例子：格子是节点，四方向相邻的可通行格子之间有边。观察队列、障碍和最终还原的最短路径，它们对应上面图模型的同一套 BFS 规则。

```python
from collections import deque

def shortest_steps(graph, start):
    distance = {start: 0}
    queue = deque([start])
    while queue:
        node = queue.popleft()
        for neighbor in graph.get(node, []):
            if neighbor not in distance:
                distance[neighbor] = distance[node] + 1
                queue.append(neighbor)
    return distance
```

发现时就标记，而不是等出队后再标记，否则同一节点可能被多个前驱反复加入队列。邻接表表示下时间 O(V + E)，额外空间 O(V)。返回字典中不存在的节点表示不可达。若要返回路径，再记录每个节点的首次发现前驱，最后从终点逆向还原。

## 多源传播与依赖图

多源 BFS 只需把所有起点同时放入队列，距离都设为零。它们像同一时刻启动的波前，计算每个位置距离最近起点的步数。网格题中别忘了墙、边界与四方向或八方向的差别；将不可通行位置加入队列会悄悄改变图的含义。

拓扑排序也使用队列，但入队条件变成“当前入度为零”。移走一个节点后，减少它指向的邻居的入度。若最终处理节点数少于总数，剩余部分存在有向环。**不变量是队列中的节点已经没有未处理的前置依赖。** 这里的层数不一定是业务完成时间：如果任务耗时不同，还需额外计算最早完成时间。

例如任务 A 完成后才能做 C，B 完成后也才能做 C。初始 A、B 均可执行，C 需等两条入边都被消除后才入队。一个常见错误是把“课程依赖谁”的边方向建反；用只有两个任务的例子即可验证方向。

## 最短路径的保证从哪里来

队列中最早加入的节点最早处理。开始只有距离零的起点；处理完这一层时，只会产生距离一的节点；处理距离一的节点时，产生的未访问节点距离为二。由此逐层推下去，任何节点第一次被发现时，都不可能还有一条更短的路径尚未处理。若更短路径存在，它的倒数第二个节点本应更早出队。

这个证明同时解释了两个实现细节。第一，距离在入队时写入，后续边看见标记便不再加入。第二，队列必须先进先出；换成栈后会沿着一条分支走到底，首次发现就不再保证最短。Python 列表的 `pop(0)` 虽然语义正确，却会移动后面的元素；使用 `deque.popleft()` 才能保持每次队列操作的常数成本。

例如从 A 到 D 有 A→B→D 和 A→C→E→D 两条路。DFS 若先访问 C，就可能先找到三步路径；BFS 会在距离二的那一层找到 D。给边附上不同权重以后，“两步”也未必便宜：两条权重 100 的边会比三条权重 1 的边更贵。非负权最短路通常使用 Dijkstra；只有权重为零和一时，可以考虑双端队列的 0-1 BFS。

## 记录父节点，返回可以走的路线

距离只能回答走几步。要显示导航路线，可以在首次发现节点时记录它由谁到达。下面假设网格为非空矩形，零表示可走，一表示障碍，坐标使用从零开始的 `(行, 列)`；起终点必须在网格范围内。

```python
from collections import deque

def grid_path(grid, start, target):
    rows, cols = len(grid), len(grid[0])
    if grid[start[0]][start[1]] or grid[target[0]][target[1]]:
        return []
    parent = {start: None}
    queue = deque([start])
    while queue:
        cell = queue.popleft()
        if cell == target:
            path = []
            while cell is not None:
                path.append(cell)
                cell = parent[cell]
            return path[::-1]
        r, c = cell
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nxt = (r + dr, c + dc)
            nr, nc = nxt
            if (0 <= nr < rows and 0 <= nc < cols
                    and grid[nr][nc] == 0 and nxt not in parent):
                parent[nxt] = cell
                queue.append(nxt)
    return []
```

返回路径包含起点和终点，所以步数为路径长度减一。起点就是终点且可以通行时，返回只有一个坐标的列表；不可达时返回空列表。网格最多访问行数乘列数个格子，每格检查四条边，时间和空间均为 O(行数 × 列数)。动画中的路线可能与另一份程序不同：邻居访问顺序会改变选中的最短路径，但不会改变它的长度。

多源 BFS 可以复用这一结构。把所有源点的父节点设为空，并同时入队，就会形成若干棵搜索树；每个格子归属于最先到达它的源点。只要所有源点在同一轮初始化，就能模拟同时传播。若先完整跑完一个源点再处理另一个，就需要额外比较距离，已经失去了这份简单实现的保证。

## 拓扑排序的完整实现

设编号从零到 n 减一，边 `(u,v)` 表示任务 u 必须先于 v。以下函数返回一种合法执行顺序，有环时返回 `None`。无依赖任务也要放进图中，否则会少算节点。

```python
from collections import deque

def topological_order(n, edges):
    graph = [[] for _ in range(n)]
    indegree = [0] * n
    for u, v in edges:
        graph[u].append(v)
        indegree[v] += 1
    queue = deque(i for i in range(n) if indegree[i] == 0)
    order = []
    while queue:
        u = queue.popleft()
        order.append(u)
        for v in graph[u]:
            indegree[v] -= 1
            if indegree[v] == 0:
                queue.append(v)
    return order if len(order) == n else None
```

每条边恰好使入度增加一次、减少一次，时间 O(V + E)，存图空间 O(V + E)。若输入包含重复边，这段代码会把它们一致地计入和扣除，结果仍正确；若建图时去重，计入度时也必须去重，不能只改一边。

考虑依赖 0→2、1→2、2→3。初始队列为 `[0,1]`，处理 0 后节点 2 的入度从二变一，仍不能执行；处理 1 后才降到零。若另外存在 3→2，则 2 和 3 互相等待，队列会在处理两个节点后耗尽。剩余节点不一定都在环上，也可能只是依赖环中的任务；因此“未被处理”等于“无法完成”，不等于“每一个都属于环”。

拓扑顺序一般不唯一。若任一步有多个零入度节点，任选一个都合法；要求字典序最小才需要换成最小堆。要计算不同耗时任务的最早完成时间，则在这份顺序上继续做动态规划：任务开始时间为所有前驱完成时间的最大值，再加自身耗时。队列轮数只在每个任务耗时相同、允许并行时才可以直接解释为完成轮数。

## 图里没有出现在任何边上的节点

一个图有五个节点但只有一条边，剩下三个孤立节点仍然属于输入。统计连通块时要从全部节点枚举起点，每发现一个未访问节点便开始一次遍历；只从边的端点收集节点，会漏掉它们。与此相反，求某个起点到其他节点的距离时，无法到达的节点就应该保持未访问，不能为了遍历完整而把距离重新设成零。

网格同样要区分“没有被搜索到”和“障碍”。前者可能是不可达的可通行位置，后者根本不属于可走图。多源传播求总时间时，只看已访问节点的最大距离还不够：如果仍有必须传播到但不可达的格子，结果应按题意返回失败标记。比如一枚新鲜橘子被墙包围，即使其余区域都在三轮内完成，也不能把答案写成三。
