# 栈与堆：保留尚未解决的候选

括号匹配要处理最近一个尚未闭合的括号，排行榜要找到当前分数最低的入围者。这两种需求分别对应栈和堆。栈按后进先出的顺序取元素，堆按优先级取元素；二者都无需把所有数据完整排序。

## 普通栈：最近打开的括号先关闭

字符串 `([])` 中，看到左圆括号先放入栈，接着放入左方括号。遇到右方括号时，只能和栈顶的左方括号配对。假如字符串是 `([)]`，虽然每种括号的数量都相同，关闭顺序却不合法；只统计数量无法发现这个错误。

```python
def valid_brackets(text):
    # 输入约定只含 ()[]{}。
    matching = {')': '(', ']': '[', '}': '{'}
    stack = []
    for char in text:
        if char in '([{':
            stack.append(char)
        elif not stack or stack.pop() != matching[char]:
            return False
    return not stack
```

遇到右括号而栈为空，表示没有可配对的左括号；扫描完成仍有元素，表示部分左括号没有闭合。空字符串在此约定下合法。每个括号最多入栈、出栈各一次，时间 O(n)，最坏空间 O(n)，例如全部都是左括号时栈会一直增长。

Python 列表尾部的 `append` 和 `pop` 适合实现栈。删除列表首元素会移动其后元素，单次可能需要 O(n)，因此不能把它当作同样便宜的栈操作。栈保存的也不一定是字符，可以是尚未完成的函数状态或数组下标。

## 单调栈：等待更大元素

有一组每日观测值 `[4, 2, 5, 3]`，希望知道每个位置要等待多少步，才会遇到严格更大的值。保存尚未找到答案的下标，令栈中对应的值从底到顶单调不增。新值到达时，可以连续解决栈顶那些比它小的位置。

**不变量：栈中的每个位置都还没有在已扫描后缀里遇到更大值。** 当值五使值二和四出栈时，五就是它们右侧第一个更大值，因为此前扫描过的位置都没能解决它们。相等值不能出栈，否则会把“严格更大”误解成“大于等于”。

| 处理值 | 处理前未解决下标 | 本轮解决 | 处理后未解决下标 |
| --- | --- | --- | --- |
| 4 | 空 | 无 | 0 |
| 2 | 0 | 无 | 0、1 |
| 5 | 0、1 | 下标 1 等 1 步；下标 0 等 2 步 | 2 |
| 3 | 2 | 无 | 2、3 |

```python
def steps_until_greater(values):
    answer = [0] * len(values)
    pending = []
    for i, value in enumerate(values):
        while pending and values[pending[-1]] < value:
            old = pending.pop()
            answer[old] = i - old
        pending.append(i)
    return answer
```

每个下标入栈一次、出栈最多一次，因此时间 O(n)，额外空间 O(n)。返回零表示后面没有更大值。若问题要求返回更大元素本身，只需改变记录答案的方式；若要求循环数组，还需要重新设计扫描范围与入栈规则，不能简单拼接答案。

暴力解会从每个位置向右扫描，遇到更大的值才停止。在严格递减的输入上，每个位置都扫描到末尾，共做 n(n − 1) / 2 次比较。单调栈把这些尚未找到答案的位置集中保存，新的值只和栈顶比较。之所以可以跳过下面的候选，是因为栈顶都不小于新值时，更下面的值只会更大，也不可能被新值解决。

例如 `[4,4,5]` 的答案为 `[2,1,0]`。处理第二个 4 时不能弹出第一个 4，因为相等不符合“严格更大”。处理 5 时两个位置依次出栈。若改成找“大于等于”的下一个值，条件才改为 `<=`，同一输入的结果也相应变为 `[1,1,0]`。

循环嵌套不意味着每个元素都执行 n 次内层操作。一个下标弹出后永远不会再次进入这次扫描的栈，所有弹出操作总数不超过 n。这叫均摊分析：把一整段操作的总成本分摊到每个元素，与“输入随机时平均表现好”是不同的理由。

## 堆：流式保留前 K 大

如果输入持续到达，只需保留最大的 k 个值，可以维护大小不超过 k 的最小堆。堆顶是这 k 个候选中最弱的一个，新值只有超过它才值得替换。处理完任意前缀后，堆保存该前缀中最大的至多 k 个值，这就是正确性不变量。

```python
import heapq

def largest_k(values, k):
    if k <= 0:
        return []
    heap = []
    for value in values:
        if len(heap) < k:
            heapq.heappush(heap, value)
        elif value > heap[0]:
            heapq.heapreplace(heap, value)
    return sorted(heap, reverse=True)
```

当 1 ≤ k ≤ n 时，维护时间 O(n log(k + 1))，最后排序 O(k log k)，空间 O(k)。这里保留重复值；如果业务要求不同值，需要额外去重，并重新解释成本。堆不是完整有序数组，除了堆顶，不能假定任意位置都有排序含义。

## 最小堆的结构与替换过程

二叉最小堆可以放在数组中。下标 i 的孩子是 2i + 1 和 2i + 2，父节点不大于孩子；因而根节点最小，但两个兄弟之间没有固定大小顺序。插入时先放在末尾，再和父节点比较并向上调整；取出最小值时，用最后一个元素补到根部，再向下调整。树高为 O(log n)，决定了这些操作的成本。

```text
        3                  数组：[3, 7, 5, 9, 8]
      /   \                7 可以比右边的 5 大
     7     5               只要求父节点 <= 自己的孩子
    / \
   9   8
```

对数据 `[6,2,9,4,8]` 保留最大的 3 项，堆的变化如下。表中按内部堆数组展示，不是排名顺序。

| 新值 | 操作 | 堆中的候选 |
| --- | --- | --- |
| 6 | 不足 3 项，加入 | `[6]` |
| 2 | 加入并向上调整 | `[2,6]` |
| 9 | 加入 | `[2,6,9]` |
| 4 | 替换最小的 2 | `[4,6,9]` |
| 8 | 替换最小的 4 | `[6,8,9]` |

最后堆顶 6 就是第 3 大的值。若只要求第 k 大，无需再排序；若要从大到小返回 k 项，才需要代码中的排序步骤。k 大于输入长度时，这段函数返回全部输入值；具体题目若要求 k 必须合法，应改成检查并拒绝非法值，不能直接读一个空堆的堆顶。

堆顶被替换之所以安全，是因为当前已经有 k 个值不小于它，后面新增数据不会让它重新挤入前 k 大。这个结论允许丢弃旧候选，无须保存整条历史数据。若窗口会过期、之前的值会删除，条件已经改变，单纯的固定大小堆就不够用了。

## 避免把堆用成排序后的数组

`heapq.heapify` 可以把已有列表在线性时间内建堆，但得到的列表并没有完整排序。取前 k 个数组位置不会得到最小的 k 个值，必须反复弹出堆顶。若元素是任务对象，可存 `(priority, sequence, task)`；同优先级时用递增的 sequence 比较，避免语言继续比较无法排序的 task 对象。

对一次性输入找第 k 大，排序简单、可直接得到所有排名，通常 O(n log n)；大小 k 的堆只保留需要的候选，适合流式输入；快速选择通常有线性期望时间，但朴素选主元方案可能退化到 O(n²)，而且会重排输入。选择哪一种要结合是否需要全部顺序、是否允许修改输入、数据是否持续到达。

测试单调栈时可以用严格递增、严格递减和全部相等的数组，分别检查连续弹出、始终不弹出以及等号规则。测试堆时让 k 为 1、等于长度、超过长度，并加入负数和重复值。上述函数保留重复次数，因此 `[5,5,2]` 的前两大应是 `[5,5]`。

## 多条有序序列合并时，堆里放谁

假设三个数据源分别按时间升序给出事件。要输出全局最早的事件，只需比较每个数据源尚未处理的第一条；同一来源后面的事件不可能比它更早。因此堆中每个来源只放一条候选，弹出一条后，再把同来源的下一条放进来。

例如三条序列为 `[1,8]`、`[2,4]`、`[3,9]`，最初候选为 1、2、3。弹出 1 后加入 8，下一次便弹出 2；弹出 2 后加入 4，之后顺序为 3、4、8、9。堆始终保存各序列的当前头部，不必把全部元素都放进去。

设总共输出 N 项、来源数为 k，每次取出和补入的成本为 O(log(k + 1))，总时间 O(N log(k + 1))，候选空间 O(k)。来源为空时不放入候选；某个来源耗尽后无需补入。若两个事件时间相同，可以用来源编号和来源内位置打破平局，明确相同时间的输出规则。

这与保留前 k 大的堆有不同的不变量：一个保存排名候选，另一个保存每条序列最早尚未输出的项目。遇到新题时写出堆内每一项的具体含义，才能判断弹出后是否还应补入其他元素。
