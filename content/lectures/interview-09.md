# 动态规划：让状态包含未来需要的信息

动态规划适用于重复子问题，但“有重复”还不足以写出正确状态。一个好状态应该让后续决策不再需要回看完整历史。面试时先用自然语言定义状态，再写转移式、初始值和计算顺序，最后才考虑压缩空间。很多难以调试的 DP，根源都是状态含义中途发生了变化。

## 从不相邻选择开始

给出非负收益 `[2, 7, 9, 3, 1]`，不能选择相邻位置，求最大总收益。定义 `best[i]` 为只考虑前 i 个位置时能取得的最大收益。面对最后一个位置，只有两类选择：不选它，保留 `best[i-1]`；选它，则前一个位置不能选，收益为 `best[i-2] + values[i-1]`。

**状态不变量：计算完第 i 步后，best[i] 已经覆盖前 i 个位置的所有合法选法。** 两种分支互斥且穷尽，因此取较大值即可。不是因为“看上去应该取 max”，而是因为我们已经把所有可能答案分完类。

对于本节序列，逐步结果如下。

| 已考虑位置数 | 不选当前 | 选当前 | 最优值 |
| --- | --- | --- | --- |
| 1 | 0 | 2 | 2 |
| 2 | 2 | 7 | 7 |
| 3 | 7 | 2 + 9 | 11 |
| 4 | 11 | 7 + 3 | 11 |
| 5 | 11 | 11 + 1 | 12 |

## 先证明，再压缩

```python
def best_non_adjacent(values):
    two_back = one_back = 0
    for value in values:
        current = max(one_back, two_back + value)
        two_back, one_back = one_back, current
    return one_back
```

每次转移只需要前两个状态，所以时间 O(n)、额外空间 O(1)。空输入返回零；这里允许一个都不选。如果题目强制至少选一个元素，且允许负数，那么初始条件就不能直接照搬。只保存两个数也无法直接还原选择路径；需要输出具体选择时，应保留额外决策或重新计算。

## 最优值、计数与可行性不是同一种 DP

硬币问题如果求最少硬币数，状态可以初始化为不可达，并用较小值更新；如果求组成金额的方法数，则要累加方案，而且遍历顺序会决定是否把不同顺序视为不同方案。不能只把 `min` 改为加号，就认为完成了从优化到计数的转换。

下面动画换用一个独立的零钱兑换例子：硬币面额为 `[1, 3, 4]`，目标金额为六，每种硬币可以重复使用。`dp[x]` 表示凑出金额 x 的最少硬币数，初始 `dp[0] = 0`，其余为不可达。每个硬币 coin 带来候选 `dp[x - coin] + 1`，最终六可以由三加三组成，答案为二。如果贪心地先取最大面额四，就会得到四加一加一，需要三枚硬币。观察它与前面不相邻选择在“状态定义”和“依赖方向”上的差别。

二维字符串 DP 则常用两个前缀长度作为状态。处理当前位置是否匹配时，应明确依赖的是左上、左边还是上边。压缩成一维后，旧值可能被覆盖，所以遍历方向属于正确性的一部分。建议在首次实现时保留完整表格，手推一个很短的反例再压缩。

常见失败包括把零同时当成“最优值为零”和“尚未计算”、遗漏空前缀边界、以及将需要未来信息的转移按正向顺序计算。记忆化搜索和表格法只是计算顺序不同，状态定义与正确性证明仍然相同。
