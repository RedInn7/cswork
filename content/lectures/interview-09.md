# 动态规划：状态、转移与计算顺序

动态规划适用于重复子问题，但“有重复”还不足以写出正确状态。一个好状态应该让后续决策不再需要回看完整历史。可以先用自然语言定义状态，再写转移式、初始值和计算顺序，最后才考虑压缩空间。很多难以调试的 DP，根源都是状态含义中途发生了变化。

## 从不相邻选择开始

给出非负收益 `[2, 7, 9, 3, 1]`，不能选择相邻位置，求最大总收益。定义 `best[i]` 为只考虑前 i 个位置时能取得的最大收益。面对最后一个位置，只有两类选择：不选它，保留 `best[i-1]`；选它，则前一个位置不能选，收益为 `best[i-2] + values[i-1]`。

**状态不变量：计算完第 i 步后，best[i] 已经覆盖前 i 个位置的所有合法选法。** 两种分支互斥且穷尽，因此取较大值即可。每个合法答案都属于其中一类，因此取最大值不会遗漏更好的选择。

对于本节序列，逐步结果如下。

| 已考虑位置数 | 不选当前 | 选当前 | 最优值 |
| --- | --- | --- | --- |
| 1 | 0 | 2 | 2 |
| 2 | 2 | 7 | 7 |
| 3 | 7 | 2 + 9 | 11 |
| 4 | 11 | 7 + 3 | 11 |
| 5 | 11 | 11 + 1 | 12 |

## 先证明，再压缩

```python
def best_non_adjacent(values):
    two_back = one_back = 0
    for value in values:
        current = max(one_back, two_back + value)
        two_back, one_back = one_back, current
    return one_back
```

每次转移只需要前两个状态，所以时间 O(n)、额外空间 O(1)。空输入返回零；这里允许一个都不选。如果题目强制至少选一个元素，且允许负数，那么初始条件就不能直接照搬。只保存两个数也无法直接还原选择路径；需要输出具体选择时，应保留额外决策或重新计算。

## 最优值、计数与可行性不是同一种 DP

硬币问题如果求最少硬币数，状态可以初始化为不可达，并用较小值更新；如果求组成金额的方法数，则要累加方案，而且遍历顺序会决定是否把不同顺序视为不同方案。不能只把 `min` 改为加号，就认为完成了从优化到计数的转换。

下面动画换用一个独立的零钱兑换例子：硬币面额为 `[1, 3, 4]`，目标金额为六，每种硬币可以重复使用。`dp[x]` 表示凑出金额 x 的最少硬币数，初始 `dp[0] = 0`，其余为不可达。每个硬币 coin 带来候选 `dp[x - coin] + 1`，最终六可以由三加三组成，答案为二。如果贪心地先取最大面额四，就会得到四加一加一，需要三枚硬币。观察它与前面不相邻选择在“状态定义”和“依赖方向”上的差别。

```algorithm-demo

```

二维字符串 DP 则常用两个前缀长度作为状态。处理当前位置是否匹配时，应明确依赖的是左上、左边还是上边。压缩成一维后，旧值可能被覆盖，所以遍历方向属于正确性的一部分。建议在首次实现时保留完整表格，手推一个很短的反例再压缩。

常见失败包括把零同时当成“最优值为零”和“尚未计算”、遗漏空前缀边界、以及将需要未来信息的转移按正向顺序计算。记忆化搜索和表格法只是计算顺序不同，状态定义与正确性证明仍然相同。

## 从枚举最后一步得到零钱转移

目标金额为 x 时，设最后一枚硬币是 coin，前面必须先凑出 x 减 coin。枚举所有不超过 x 的面额，就覆盖了所有可能的最后一步；从可达前驱中取最少枚数，再加一。这样既给出了转移式，也说明为什么不能只试最大面额。硬币必须为正整数，否则金额依赖可能指向自身或更大的状态，按金额递增的计算顺序便不再成立。

```python
def min_coins(coins, amount):
    unreachable = amount + 1
    dp = [unreachable] * (amount + 1)
    dp[0] = 0
    for total in range(1, amount + 1):
        for coin in coins:
            if coin <= total:
                dp[total] = min(dp[total], dp[total - coin] + 1)
    return -1 if dp[amount] == unreachable else dp[amount]
```

代码约定金额为非负整数，面额均为正整数。因为每枚硬币至少为一，任何可达金额的最优枚数都不超过金额本身，`amount + 1` 可以安全代表不可达。空面额列表在目标零时返回零，在正目标时返回负一。若共有 k 种面额、目标为 A，时间 O(Ak)、空间 O(A)；这里的规模取决于金额的数值，金额达到十亿时不能直接分配这么大的数组。

对动画中的 `[1,3,4]`，各金额的最少枚数如下。计算六时会比较五的答案加一、三的答案加一、二的答案加一，即三、二、三，所以选择两个三。

| 金额 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 最少枚数 | 0 | 1 | 2 | 1 | 1 | 2 | 2 |
| 一种组成 | 空 | 1 | 1+1 | 3 | 4 | 1+4 | 3+3 |

## 循环顺序会改变计数对象

若改问金额三由面额一、二组成的方案数，先确认是否把 `1+2` 与 `2+1` 算成同一个方案。求无序组合时，可以依次允许使用每一种面额；处理面额二时，前面不会再出现一个“随后才加入面额一”的独立顺序。

```python
def coin_combinations(coins, amount):
    ways = [0] * (amount + 1)
    ways[0] = 1
    for coin in sorted(set(coins)):
        for total in range(coin, amount + 1):
            ways[total] += ways[total - coin]
    return ways[amount]
```

这里同样只接受正整数面额。金额在内层从小到大，意味着当前面额可以重复使用；倒着遍历则会让每种面额最多使用一次。把金额放在外层、面额放在内层，则是在枚举最后一枚硬币，会得到有序序列数。以目标三为例，无序组合为 `1+1+1` 和 `1+2`，共二种；有序序列额外区分 `2+1`，共三种。零金额初始化为一，是因为“不选任何硬币”恰好是一种组成方法，后续所有方案都从它扩展。

## 两个字符串为什么需要两个下标

最长公共子序列不要求字符连续，只要求相对顺序相同。定义 `dp[i][j]` 为第一个字符串前 i 个字符与第二个字符串前 j 个字符的最长公共子序列长度。只记录 i 不够：相同的第一个前缀，面对不同长度的第二个前缀，会有不同的可选匹配位置。

若两个末尾字符相同，可以把它接在两个更短前缀的公共子序列后，得到左上方加一。若不同，一个公共子序列不可能同时以这两个不同字符结尾，因此至少舍弃一边的末尾，在上方与左方取较大值。

```python
def lcs_length(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[-1][-1]
```

对 `a="abc"`、`b="ac"`，表格如下。行列零都代表空前缀，它与任何字符串的公共子序列长度都是零。最后的二对应 `ac`；若要求连续公共子串，这个答案就不成立，因为 `ac` 在第一个字符串中不连续。

| a 的前缀 / b 的前缀 | 空 | a | ac |
| --- | --- | --- | --- |
| 空 | 0 | 0 | 0 |
| a | 0 | 1 | 1 |
| ab | 0 | 1 | 1 |
| abc | 0 | 1 | 2 |

时间和空间均为 O(mn)。Python 创建二维表时必须逐行生成，不能写成 `[[0] * width] * height`，否则每一行都引用同一个列表。若压缩成一行，更新 `dp[j]` 前还需保存左上方旧值；当前 `dp[j-1]` 已属于新行，而当前 `dp[j]` 仍属于旧行。没有明确区分新旧，压缩会把错误藏在很短的代码里。

## 最优值以外的信息

要返回实际子序列，可以从表格右下角逆推：字符相同就记录字符并走向左上，否则走向值较大的上方或左方，最后逆序得到结果。相等时任选一边，会返回某一种最优解；若要求字典序最小，就需要额外处理，不能依赖随意的平局规则。

记忆化搜索也要使用同样完整的状态。用 `(i,j)` 缓存 LCS 可以避免重复计算；只用 i 缓存会把不同 j 的答案混在一起。缓存范围应局限于当前输入，或者把输入身份也纳入缓存键，否则不同字符串之间可能错误复用结果。
