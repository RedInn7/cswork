# 前缀和：把区间问题改写成两个端点

每天的订单量已经存成数组，需要多次查询“第几天到第几天一共有多少单”。每次逐项相加都能得到答案，但不同查询可能覆盖同一段日期。前缀和先累计到每个位置的总数，再用两个累计值相减回答查询。预处理花 O(n)，之后每次查询只做一次减法。

## 一个额外的零消除特殊情况

定义 `prefix[i]` 为前 i 个元素的和，长度为 n 的数组对应 n + 1 个前缀值，且 `prefix[0] = 0`。半开区间 `[left, right)` 的和为 `prefix[right] - prefix[left]`。这个定义能统一处理从下标零开始的区间，也能表达长度为零的区间。

| 原数组 | 2 | -1 | 3 | -2 |
| --- | --- | --- | --- | --- |
| 加入前的前缀和 | 0 | 2 | 1 | 4 |
| 加入后的前缀和 | 2 | 1 | 4 | 2 |

例如 `[1, 3)` 的和为 `prefix[3] - prefix[1] = 4 - 2 = 2`。不要把半开区间公式和闭区间的右端点混用。第一次写程序时，可以给数组旁边同时画出元素下标与前缀下标。

```text
前缀边界    0       1       2       3       4
数组元素       2      -1       3      -2
累计和      0       2       1       4       2
                    └── 查询 [1,3) ──┘
```

```python
def build_prefix(values):
    prefix = [0]
    for value in values:
        prefix.append(prefix[-1] + value)
    return prefix

def range_sum(prefix, left, right):
    # 调用者保证 0 <= left <= right < len(prefix)。
    return prefix[right] - prefix[left]
```

数组长度为 n，查询次数为 q，逐次扫描的最坏总工作量为 O(nq)，前缀和将它变为 O(n + q)，额外空间 O(n)。如果只查一次整段和，直接累加已经是 O(n)，未必值得额外建表。修改一个数组元素会影响其后所有前缀；如果要求查询和修改交替发生很多次，通常需要树状数组或线段树。

## 从求和到计数

现在要求统计和等于 target 的非空连续子数组数量。固定右端点的前缀和为 total，需要寻找此前出现过多少次 `total - target`。于是哈希表保存的应当是次数，不是最后出现的位置。初始的零前缀出现一次，使从数组开头开始的合法区间也能被统计。

```python
def count_target_ranges(values, target):
    frequency = {0: 1}
    total = answer = 0
    for value in values:
        total += value
        answer += frequency.get(total - target, 0)
        frequency[total] = frequency.get(total, 0) + 1
    return answer
```

**循环不变量：查询时，频次表只包含当前位置之前的前缀。** 必须先统计答案再加入当前前缀，否则 target 为零时会把空区间误算进去。以 `[1, -1, 1]`、target 为一为例，三步分别新增一、零、二个区间，答案为三。第三步有两个合法起点，正好说明为什么不能只保存一个下标。

| 读入值 | 当前 total | 要找的旧前缀 | 旧前缀的次数 | 新增区间 |
| --- | --- | --- | --- | --- |
| 1 | 1 | 0 | 1 | 第一个 1 |
| −1 | 0 | −1 | 0 | 无 |
| 1 | 1 | 0 | 2 | 整个数组；最后一个 1 |

两个零前缀分别位于数组开头之前，以及读完 `[1,-1]` 之后。它们的累计值相同，位置却不同，所以形成不同子数组。全零数组尤其适合检查这一点：长度为 3 时，和为 0 的非空区间有 6 个。把频次表换成集合只能得到 3，先插入再查询则会多算 3 个空区间。

## 复杂度与变体边界

哈希操作平均为常数时间时，总时间 O(n)，额外空间 O(n)。答案数量最大可达到 n(n + 1) / 2，在固定宽度整数语言中要检查是否需要 64 位整数；前缀和本身也可能溢出。Python 整数避免固定宽度溢出，但并不意味着任意大整数运算都完全没有成本。

如果要求区间和能被 k 整除，可以比较前缀余数是否相同；在余数可能为负的语言中，需要统一规范到相同范围。如果要求最大值，两个前缀最大值无法通过简单相减还原区间最大值，不能机械推广。差分数组则解决另一个方向的问题：把多次区间加法转换为端点修改，最后再累加还原。

## 同一个前缀状态，按目标保存不同信息

若要求和等于 target 的最长区间，固定右端点后，希望合法左端点越早越好。因此字典保存某个前缀值第一次出现的位置，后续相同前缀不覆盖。若要求最短非空区间，则要找最近的合法左端，保存最后一次位置，但仍然先查询、再更新。计数题需要所有位置的数量，不能只留下最早或最晚的一个。

“和可以被 k 整除”的推导是：两个前缀之差是 k 的倍数，当且仅当它们模 k 后相等。例如前缀值 2 和 7 对 k = 5 的余数都为 2，二者间的区间和就是 5。只需把前面的 `total` 改成余数状态，并查询同余状态的次数。要求 k 为正；C++ 或 Java 中可用 `(sum % k + k) % k` 统一负数余数，Python 对正 k 的 `%` 已经得到非负结果。

## 差分：给一整段加数，只记两个边界

假设五个位置初始都是 0，要给半开区间 `[1,4)` 都加 3，再给 `[2,5)` 都减 1。逐项修改要处理 6 个位置。差分记录的是“从这里开始，增量改变多少”：第一项操作在 1 处加 3、4 处减 3；第二项在 2 处减 1、5 处加 1。把差分累加，便还原出每个位置的最终增量。

| 下标 | 0 | 1 | 2 | 3 | 4 | 5（哨兵） |
| --- | --- | --- | --- | --- | --- | --- |
| 两次操作后的差分 | 0 | 3 | −1 | 0 | −3 | 1 |
| 累加后的值 | 0 | 3 | 2 | 2 | −1 | 不输出 |

```python
def apply_additions(n, updates):
    # updates 中每项为 (left, right, delta)，区间为 [left,right)。
    diff = [0] * (n + 1)
    for left, right, delta in updates:
        diff[left] += delta
        diff[right] -= delta
    answer = []
    running = 0
    for i in range(n):
        running += diff[i]
        answer.append(running)
    return answer
```

长度 n + 1 使 right = n 的操作无需特殊判断，最后只输出前 n 项。q 次更新和一次还原共 O(q + n) 时间、O(n) 额外空间。它适合所有修改结束后统一查询结果；若每次修改后都立即查询，重新还原仍要 O(n)，不能宣称整套在线操作都是常数时间。

## 二维前缀和中的重叠部分

网格里的矩形和使用相同思想。令 P[r][c] 表示前 r 行、前 c 列的总和，补出第零行和第零列。查询行区间 `[r1,r2)`、列区间 `[c1,c2)` 时，从右下角前缀中减去上边和左边的区域，再把被减去两次的左上区域加回来。

公式是 `P[r2][c2] - P[r1][c2] - P[r2][c1] + P[r1][c1]`。例如矩阵 `[[1,2,3],[4,5,6]]` 查询两行中的后两列，总和是 2 + 3 + 5 + 6 = 16，也等于整块 21 减去第一列 5。一般矩形的左上角不在零边界时，最后的加回项就不能省略。预处理 O(行数 × 列数)，每次矩形查询 O(1)，代价是同样规模的存储。

## 前缀和不能替代所有区间数据结构

求和能够相减，是因为已经累计的旧部分可以被消去。区间异或也有类似性质：一个值异或两次会抵消。但前缀最大值没有这样的逆操作。对 `[5,1,2]` 和 `[5,3,4]`，所有前缀最大值都是 5，后两项的最大值却分别为 2 和 4；仅凭前缀最大值表不可能区分它们。

乘积也不能简单照搬除法。输入存在零时，前缀乘积会变成零，无法用两个零相除恢复中间结果。“除自身以外数组的乘积”通常分别累积左侧和右侧乘积，再相乘；空前缀和空后缀的乘积定义为 1。这个初值和求和的 0 不同，取决于对应运算的单位元。

## 用枚举验证计数

计数题很容易少算重复状态，检查几个手写样例不够直观。可以固定左端，右端逐次扩展并维护当前和，每次等于目标就加一。这个暴力方法只需 O(n²)，适合长度不超过几十的小数组，且与哈希计数的实现路径不同。对长度很短、元素取 −1、0、1 的所有数组逐个比较两个答案，能覆盖重复前缀、负数抵消和全零等情况。

区间端点检查可以独立做：对每个合法的 left、right，把 `range_sum` 和直接求切片和比较。尤其保留 left = right 的空区间，以及 right = n 的最后边界；这两类测试通常能发现少建一个前缀值、右端混用闭区间等错误。

实现前先检查数值范围：十万个元素，每项可能达到十亿，累计值可能达到十的十四次方，32 位有符号整数无法容纳。Java 可用 long，C++ 可用 long long；相加时也要确保中间表达式已经使用宽整数。仅在最终赋值时换类型，不能修复此前已经发生的溢出。
