# 并查集与 Trie：连通关系和前缀查询

有些题目反复询问“是否属于同一组”，另一些题目反复询问“是否存在这个前缀”。前者可以考虑并查集，后者可以考虑 Trie。它们都通过保留结构减少重复搜索，但支持的操作不同；先确认查询需求，再判断是否值得构建额外索引。

## 并查集：只关心属于哪个连通块

初始四个节点各成一组。依次加入连接 `(0, 1)`、`(2, 3)`、`(1, 3)`，组数从四变三、再变二、最后变一。并查集用一棵父指针树表示一组，根节点是代表。代表只是标识，不必是最小元素，也不代表真实业务层级。

| 操作 | 连通分组 | 组数 |
| --- | --- | --- |
| 初始 | {0}、{1}、{2}、{3} | 4 |
| 合并 0、1 | {0,1}、{2}、{3} | 3 |
| 合并 2、3 | {0,1}、{2,3} | 2 |
| 合并 1、3 | {0,1,2,3} | 1 |

**不变量：两个节点属于同一组，当且仅当它们沿父指针找到同一个根。** 只合并两个根，可以保持分组关系；按大小合并避免把大树挂到小树下面，路径压缩让后续查询更短。

```python
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.components = n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a, b = self.find(a), self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        self.components -= 1
        return True
```

初始化 O(n)，后续 m 次操作的均摊总成本 O(m α(n))，空间 O(n)；α 是增长极慢的反阿克曼函数。它在实际规模下很小，但不能因此把理论复杂度直接等同于严格常数。输入下标需满足零到 n 减一。

普通并查集适合不断合并，不直接支持任意删除连接，也不提供两点之间的具体路径。对于一次静态连通块统计，DFS 或 BFS 同样合理。若问题涉及有向可达性，仅仅合并两个端点会丢失方向，通常不适用。

## Trie：共享前缀的搜索路径

将 `car`、`cat`、`dog` 插入 Trie，前两个单词共享 c→a，随后分别走向 r 与 t。每个节点保存下一字符的映射，并用单独的结束标记区分“完整词”和“只是前缀”。查询 `ca` 时，路径存在只能证明它是某个词的前缀，不能证明单词 `ca` 已插入。

若插入字符总数为 S，节点数至多 S + 1；单个长度为 L 的词，查询时间在子节点映射操作平均为常数的假设下为 O(L)。Trie 的节点与映射可能有较高实际内存成本。只做完整词查找时，哈希集合通常更简单；需要前缀查找时，Trie 才有明显结构优势。

## 一次合并到底改变了什么

执行 `union(1,3)` 时，先找到两个根。假设 1 指向根 0，3 指向根 2，那么真正连接的是根 2 和根 0，而不是把输入节点 3 随意挂到节点 1。挂根以后，原来整棵树中的成员都通过父指针找到新代表；无需逐个修改组内成员。若错误地只移动普通节点，有可能把它的子树从原组拆走，破坏已经确认的连接。

按大小合并时，每当一个节点所在树被挂到另一棵树下，它所属组的大小至少翻倍。仅有这一条规则，就可以把树高限制在 O(log n)。路径压缩又会在查询过程中跳过中间父节点；上面的 `find` 使用路径减半，每次让当前节点指向祖父。它与递归写法最终指向根的压缩方式不同，但都保持“成员找到同一代表”的含义。

`size` 只在根节点上有效。查询某个成员所在组的大小时，应读取 `size[find(x)]`，不能直接读取 `size[x]`。同样，代表编号可能在下一次合并后变化；若业务要显示组内最小编号，可以给根额外维护 `minimum`，合并时取两组最小值，而不应假定根天生就是最小编号。

## 用失败的合并识别冗余边

对于无向图，加入一条边之前，如果两端已经连通，原来就存在一条连接它们的路径。再加入新边便形成环。下面返回按输入顺序遇到的第一条冗余边，假设节点编号为零到 n 减一，并复用前面的 `DSU`。

```python
def first_redundant_edge(n, edges):
    groups = DSU(n)
    for u, v in edges:
        if not groups.union(u, v):
            return (u, v)
    return None
```

例如边依次为 `(0,1)`、`(1,2)`、`(0,2)`：前两次合并成功，第三次两端的根相同，返回 `(0,2)`。如果题目要最后一条冗余边，应继续扫描并更新结果；如果允许自环和重复边，也要按题目的“环”定义确认如何处理。这段代码把自环直接判为冗余，重复的无向边也会触发失败。

并查集不会保存用于连通的原始路径。上例中根的父指针即使是 2→0，也不意味着原图存在这条边。要求输出具体环时，需要另存原图并搜索路径。它也无法回答有向图中的先后可达关系：A→B 并不意味着 B→A，合并两端却会把二者视为对称关系。

## 把 Trie 的结束标记写进代码

下面的实现每个节点有字符到子节点的字典，以及一个布尔结束标记。`walk` 只负责沿路径移动，`search` 与 `starts_with` 再各自判断完整词和前缀。分开这两种查询，可以避免把存在路径误当作已经插入单词。

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.terminal = False

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        node = self.root
        for char in word:
            if char not in node.children:
                node.children[char] = TrieNode()
            node = node.children[char]
        node.terminal = True

    def walk(self, text):
        node = self.root
        for char in text:
            node = node.children.get(char)
            if node is None:
                return None
        return node

    def search(self, word):
        node = self.walk(word)
        return node is not None and node.terminal

    def starts_with(self, prefix):
        return self.walk(prefix) is not None
```

插入 `car`、`cat` 后，查询 `ca` 的完整词结果为假，前缀结果为真；随后插入 `ca`，只需给已有节点补上结束标记，不会删掉 r、t 两条分支。重复插入同一单词不会增加节点，也不会改变查询结果。插入空串会把根标为结束；空前缀始终存在，包括 Trie 尚未插入任何单词的时候。这是本实现的接口约定，若题目禁止空串，调用者可以直接沿用。

| 查询 | 插入 car、cat 后 | 再插入 ca 后 |
| --- | --- | --- |
| search(car) | 真 | 真 |
| search(ca) | 假 | 真 |
| starts_with(ca) | 真 | 真 |
| starts_with(cb) | 假 | 假 |

## 前缀剪枝与空间取舍

在网格中寻找多个单词时，普通做法是对每个单词重复回溯；Trie 可以把共同前缀合并。例如目标有 `care`、`cart`、`cat`，从格子 c 走到 a 时，这一段搜索可同时服务三个目标。走到 r 后只剩前两个；走到 b 后没有任何目标以 cab 开头，可以立刻返回。回溯状态需要同时保存网格位置、当前 Trie 节点和本条路径已经使用的格子。

单词结束并不代表搜索必须停止。找到 `car` 后还可能继续找到 `care`，因此记录答案后仍要检查子节点。同一个单词也可能由多条网格路径形成；若只要求返回单词集合，可以用集合去重，或在找到后清除对应结束标记。后者会修改 Trie，不适合还要保留原词库给下一次独立查询的接口。

固定小写字母可以用长度 26 的数组保存孩子，访问直接，但稀疏节点会浪费空间。字典只保存已有分支，适合字符集较大或分支稀少的情况；代价是对象和散列表开销。不能只比较 O(L) 就断言 Trie 一定比哈希集合快。完整词精确查找通常用集合足够，前缀查找、逐字符通配或共享前缀搜索，才需要这些额外节点。

## 删除操作需要另外设计

Trie 删除一个词时，先撤销末尾标记；只有某个节点不再是任何词的末尾、也没有孩子，才可以沿路径向上删除它。删掉 `car` 不能顺手删去 c、a，否则 `cat` 也会消失。若要记录同一个词被插入的次数，布尔结束标记还需改成计数。

普通并查集的删除更困难，因为父指针没有保存形成连通关系的全部边。删除一条边以后，原组可能仍连通，也可能拆成两组，单靠组大小无法判断。有些离线题可以倒序处理，把删除转为合并；有些需要可回滚并查集或其他动态连通算法。应根据操作顺序选择结构，不应在 `parent` 数组上随意断开一条指针。
