# 并查集与 Trie：把连接和前缀变成结构

有些题目反复询问“是否属于同一组”，另一些题目反复询问“是否存在这个前缀”。前者可以考虑并查集，后者可以考虑 Trie。它们都通过保留结构减少重复搜索，但支持的操作不同；先确认查询需求，再判断是否值得构建额外索引。

## 并查集：只关心属于哪个连通块

初始四个节点各成一组。依次加入连接 `(0, 1)`、`(2, 3)`、`(1, 3)`，组数从四变三、再变二、最后变一。并查集用一棵父指针树表示一组，根节点是代表。代表只是标识，不必是最小元素，也不代表真实业务层级。

| 操作 | 连通分组 | 组数 |
| --- | --- | --- |
| 初始 | {0}、{1}、{2}、{3} | 4 |
| 合并 0、1 | {0,1}、{2}、{3} | 3 |
| 合并 2、3 | {0,1}、{2,3} | 2 |
| 合并 1、3 | {0,1,2,3} | 1 |

**不变量：两个节点属于同一组，当且仅当它们沿父指针找到同一个根。** 只合并两个根，可以保持分组关系；按大小合并避免把大树挂到小树下面，路径压缩让后续查询更短。

```python
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.components = n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a, b = self.find(a), self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        self.components -= 1
        return True
```

初始化 O(n)，后续 m 次操作的均摊总成本 O(m α(n))，空间 O(n)；α 是增长极慢的反阿克曼函数。面试里可以说明它在实际规模下很小，但不要因此把理论复杂度直接等同于严格常数。输入下标需满足零到 n 减一。

普通并查集适合不断合并，不直接支持任意删除连接，也不提供两点之间的具体路径。对于一次静态连通块统计，DFS 或 BFS 同样合理。若问题涉及有向可达性，仅仅合并两个端点会丢失方向，通常不适用。

## Trie：共享前缀的搜索路径

将 `car`、`cat`、`dog` 插入 Trie，前两个单词共享 c→a，随后分别走向 r 与 t。每个节点保存下一字符的映射，并用单独的结束标记区分“完整词”和“只是前缀”。查询 `ca` 时，路径存在只能证明它是某个词的前缀，不能证明单词 `ca` 已插入。

若插入字符总数为 S，节点数至多 S + 1；单个长度为 L 的词，查询时间在子节点映射操作平均为常数的假设下为 O(L)。Trie 的节点与映射可能有较高实际内存成本。只做完整词查找时，哈希集合通常更简单；需要前缀查找时，Trie 才有明显结构优势。
