# 贪心与区间：选择规则与交换证明

贪心算法通常实现简洁，正确性却需要额外解释。面对一个“每次选最好”的方案，首先问：最好按什么排序？为什么这个局部选择可以出现在某个全局最优解里？如果只能举几个成功例子，还没有完成证明。区间调度是练习交换论证的好起点。

## 选择最多个互不重叠区间

约定区间采用半开形式 `[start, end)`，因此结束时刻等于下一段开始时刻可以衔接。希望从若干活动中选择最多个互不重叠活动。优先选择结束最早的活动，之后只考虑开始时刻不早于它结束的活动。

例如区间为 `[1,4)`、`[2,3)`、`[3,5)`、`[5,7)`。按结束时间排序后，依次选择 `[2,3)`、`[3,5)`、`[5,7)`，得到三个。若只按开始时间选最早的 `[1,4)`，这组例子就只能得到两个，说明“最早开始”不是足够好的贪心依据。

| 候选区间 | 上次结束时间 | 决策 |
| --- | --- | --- |
| [2,3) | 尚未选择 | 选择，结束时间变 3 |
| [1,4) | 3 | 跳过，开始时间太早 |
| [3,5) | 3 | 选择，结束时间变 5 |
| [5,7) | 5 | 选择，结束时间变 7 |

## 交换论证

取任意一个最优方案，设它第一个活动是 A；结束最早的活动是 G。将 A 换为 G，不会使后续活动冲突，因为 G 的结束时间不晚于 A。替换后活动数量不变，所以一定存在以 G 开始的最优方案。接下来对剩余活动重复同样论证。

**不变量：已经选出的活动，可以作为某个最优方案的前缀。** 这个承诺比“当前剩余时间最多”更精确，也能帮助判断变体是否适用。如果每个活动有不同收益，最大活动数量就变成最大收益问题，同样的选择规则可能失败，需要考虑加权区间 DP。

```python
def maximum_compatible(intervals):
    chosen = []
    last_end = None
    for start, end in sorted(intervals, key=lambda item: item[1]):
        if last_end is None or start >= last_end:
            chosen.append((start, end))
            last_end = end
    return chosen
```

假定每段满足 start < end。排序时间 O(n log n)，扫描时间 O(n)，排序副本和结果所需空间 O(n)。空输入返回空列表。如果题目规定端点接触也算重叠，需要把兼容条件改为严格大于，并重新检查样例。区间开闭规则是题意，不是实现偏好。

## 区间合并与可达范围

合并区间通常按开始位置排序，维护当前已合并段的最远结束位置；调度选择则按结束位置排序。两题都出现区间，但目标不同，排序键也不同。不要只根据输入形状套模板。

跳跃类题目可以维护当前能到达的最远位置。扫描到一个超过这个范围的位置，说明中间断开；否则用当前位置的跳跃能力扩张边界。正确性依赖于此前所有可达位置已经被考虑，而不是每次跳到看起来最远的一个落点。还需明确是判断可达、求最少跳数还是返回路径，这些目标需要保存的信息不同。

## 给错误规则找一个小反例

“选最短活动”看起来会留下最多空闲时间，却也可能失败。考虑 `[0,3)`、`[3,6)`、`[2,4)`，最短的是长度二的 `[2,4)`，但它同时挡住另外两段，只能选一段；选择前两段能得到二段。“选择冲突最少的活动”也需要独立证明，不能因为样例通过就套用。贪心的候选规则越像直觉，越应该先拿三四个对象寻找冲突。

最早结束的交换证明依赖所有活动价值相同。若 `[0,2)` 收益一，`[0,4)` 收益一百，按结束时间先选短活动会丢掉高收益。加权版本可先按结束时间排序，对每个活动找到与它兼容的最后一个前驱，再比较“跳过当前”和“选择当前加上前驱最优收益”。选择标准变化后，原先只保留一个结束时间已经不够。

## 合并区间维护的是覆盖范围

合并要求把覆盖的点完整保留，不能为了多留下几段而丢掉某个区间。以下使用闭区间，端点相等算相交，因此 `[1,3]` 与 `[3,5]` 合并为 `[1,5]`。输入约定起点不大于终点，单点区间允许存在。

```python
def merge_intervals(intervals):
    merged = []
    for start, end in sorted(intervals):
        if not merged or start > merged[-1][1]:
            merged.append([start, end])
        else:
            merged[-1][1] = max(merged[-1][1], end)
    return merged
```

排序后，后续区间的起点不会更早。当前区间若与最后一段分离，就也不可能与更前面的任何段相交，可以新开一段；若相交，只需扩大最后一段的右端点。已完成的更早段再也不会变化。用这个性质可以解释为什么只检查结果末尾就够，不需要逐一遍历全部已合并区间。

| 输入当前段 | 已合并结果 | 发生的变化 |
| --- | --- | --- |
| [1,8] | [1,8] | 新开一段 |
| [2,3] | [1,8] | 被包含，右端点保持八 |
| [6,10] | [1,10] | 扩大右端点 |
| [12,13] | [1,10]、[12,13] | 起点超过十，新开一段 |

时间 O(n log n)，额外空间 O(n)，没有修改调用者传入的列表。直接写 `merged[-1][1] = end` 会在第二行把八缩回三，遗漏原本覆盖的位置。半开区间若不把接触视为相交，则新开一段的条件改为大于等于；题目若希望相接的覆盖范围也合并，又可以继续使用当前条件。应先确定输出要求，再选比较符号。

## 从单次选择转为维护全部可达位置

跳跃游戏给出非负数组，站在 i 时可以向右跳零到 `nums[i]` 步，判断能否到达最后一个位置。若只跳到当前最远的落点，可能落到零而错过中途更强的起跳位置。例如 `[2,3,0,0,0]` 从零直接跳到二就无法继续，但先到一可以直达末尾。

```python
def can_reach_end(nums):
    if not nums:
        return False
    farthest = 0
    for i, step in enumerate(nums):
        if i > farthest:
            return False
        farthest = max(farthest, i + step)
        if farthest >= len(nums) - 1:
            return True
    return False
```

扫描到 i 之前，已经考虑过的可达位置共同覆盖了从零到 `farthest` 的整段前缀。这里依赖允许跳“最多”给定步数：一个位置能跳到远处，就能落在中间任何位置。如果题目改成恰好跳给定步数，可达集合可能出现空洞，仅存最大下标就不够了。

这段代码对空数组返回假，对 `[0]` 返回真，因为已经位于终点。数组中出现零不一定失败，只有当前扫描位置已经超过最远覆盖范围才说明断开。时间 O(n)、空间 O(1)。在固定宽度整数语言里，若跳跃值很大，还要避免 `i + step` 溢出，可以用更宽的整数或把范围截到终点。

## 最少跳数：把可达区间分层

判断可达之后，再求最少跳数，需要区分“当前跳数能到的边界”和“再跳一次能到的边界”。这与 BFS 按层扩展相似，但数组的连续覆盖允许只保存两个边界，无需显式把每条跳跃边加入队列。

```python
def minimum_jumps(nums):
    if not nums:
        return -1
    end = farthest = jumps = 0
    for i in range(len(nums) - 1):
        if i > farthest:
            return -1
        farthest = max(farthest, i + nums[i])
        if i == end:
            if farthest == end:
                return -1
            jumps += 1
            end = farthest
            if end >= len(nums) - 1:
                return jumps
    return jumps
```

对 `[2,3,1,1,4]`，从零扩展后第一层终点为二，跳数为一。扫描位置一、二时把下一层最远位置推到四；到达当前边界二以后，再增加一次跳数，答案为二。不能在每次 `farthest` 变大时就增加跳数，因为同一层内多个位置都可能扩大下一层范围。

循环不处理最后一个位置：到达终点已经完成，不需要再从终点起跳。单元素输入返回零，无法到达时返回负一；时间 O(n)，空间 O(1)。若要返回具体落点，还得记录哪一个位置贡献了下一层的最远范围，并保留层与层之间的选择。仅有最少次数无法直接还原路线。
