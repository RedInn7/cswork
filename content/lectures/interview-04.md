# 二分查找：寻找真假分界线

在已经排好序的数组里查找目标，可以逐个比较，也可以先检查中间元素。若中间值小于目标，中间及左边都不可能是答案，剩下的候选立即减半。重复这个过程，十万个元素大约只需十几轮判断。二分的每次移动都必须能排除一整段候选，数组有序提供了这个依据。

若数组没有排序，只比较中间元素不能判断目标在哪一侧。先排序再查找也有代价：比较排序通常需要 O(n log n)，只查询一次时往往不如直接扫描；需要查询很多次时，预处理才可能值得。排序还会改变下标含义，要求原下标的题需要额外保存对应关系。

## 用半开区间寻找第一个符合条件的位置

寻找有序数组中第一个大于等于 target 的位置，维护待确定区间 `[left, right)`。不变量是：left 左边的元素都小于 target，right 及其右侧的有效元素都大于等于 target。初始 left 为零、right 为数组长度，所以两个已确定区域都为空，不变量自然成立。

下面先用含重复值的例子检验“找到第一个”的要求：数组 `[1, 3, 3, 7, 9]`，target 为三。

| left | right | mid | 判断 | 更新 |
| --- | --- | --- | --- | --- |
| 0 | 5 | 2 | 3 ≥ 3 | right = 2 |
| 0 | 2 | 1 | 3 ≥ 3 | right = 1 |
| 0 | 1 | 0 | 1 < 3 | left = 1 |

最终 left 等于 right，返回一。命中时继续向左找，所以不会错误返回第二个三。

```python
def lower_bound(values, target):
    left, right = 0, len(values)
    while left < right:
        mid = left + (right - left) // 2
        if values[mid] >= target:
            right = mid
        else:
            left = mid + 1
    return left
```

时间 O(log n)，额外空间 O(1)。返回值可以等于 n，表示没有符合条件的元素；如果目标是检查 target 是否存在，必须先验证返回值小于 n，再访问数组。空数组会直接返回零，这个插入位置合法，但并不表示命中。

`right = mid` 并没有丢掉可能的答案 mid。虽然 mid 不再属于待检查的半开区间，它成为右边已经确定满足条件区域的起点；最后两端相遇的位置仍可能就是它。相反，`values[mid] < target` 时，mid 自己也不符合条件，所以左端必须移到 mid + 1。

```text
已确定小于 target        尚待判断          已确定 >= target
[0 ........ left)     [left, right)     [right ........ n)
                                      ↑ 允许 right = n
```

每轮都有 left ≤ mid < right。走左分支时 right 严格变小，走右分支时 left 严格变大，区间长度最终降到 0。这同时解释了为什么循环会结束。若误写 `left = mid`，当半开区间只剩一个元素时，mid 等于 left，程序便不再前进。

## 重复元素与四种边界

数组 `[1,3,3,3,8]` 中，查到某个 3 可能返回 1、2 或 3。若要统计 3 出现几次，需要找左边界和右边界：第一个大于等于 3 的位置是 1，第一个严格大于 3 的位置是 4，差值为 3。

```python
def upper_bound(values, target):
    left, right = 0, len(values)
    while left < right:
        mid = left + (right - left) // 2
        if values[mid] > target:
            right = mid
        else:
            left = mid + 1
    return left
```

最后一个小于目标的位置是 lower_bound − 1，最后一个小于等于目标的位置是 upper_bound − 1。结果为 −1 时表示不存在，不能直接用它访问 Python 列表，否则会误读最后一项。下面这些结果也可以当作边界测试。

| 数组 | 目标 | lower bound | upper bound | 命中个数 |
| --- | --- | --- | --- | --- |
| 空 | 3 | 0 | 0 | 0 |
| `[3,3]` | 3 | 0 | 2 | 2 |
| `[3,3]` | 1 | 0 | 0 | 0 |
| `[3,3]` | 5 | 2 | 2 | 0 |

## 对答案二分

如果问题问完成任务所需的最小速度，可以把“速度为 v 时能否按时完成”当作判断函数。必须证明更高速度不会让可行方案变不可行。以正整数工作量和每小时固定处理量为例，每项所需小时数是向上取整的 `work / v`，总小时数随着 v 增大不会上升。

判断一次若需要 O(n)，在大小为 R 的整数候选区间二分，总时间就是 O(n log R)，不能只报 O(log R)。上下界也要有证明：最小速度通常至少为一，上界需要确实可行。如果题目本身可能无解，应先处理无解情况，而不是让二分返回一个看似合理的数。

## 完整例子：在规定时间内处理所有工作

有若干项正整数工作量，每小时只能处理其中一项，速度为 v 时一小时最多处理 v 单位，某项剩余不足 v 也占用一整小时。要求最小整数速度，使所有工作在 hours 小时内完成。对固定速度，直接累计每项需要的小时数即可。

以 `[3,6,7,11]`、hours = 8 为例，速度 3 需要 1 + 2 + 3 + 4 = 10 小时，不可行；速度 4 需要 1 + 2 + 2 + 3 = 8 小时，可行。速度再增加，各项需要的小时数只能减少或不变，可行性按速度呈现“假、假、真、真”的顺序。

| 当前速度范围 | 尝试速度 | 所需小时 | 保留的范围 |
| --- | --- | --- | --- |
| `[1,11]` | 6 | 6 | `[1,6]` |
| `[1,6]` | 3 | 10 | `[4,6]` |
| `[4,6]` | 5 | 8 | `[4,5]` |
| `[4,5]` | 4 | 8 | `[4,4]` |

```python
def minimum_speed(workloads, hours):
    # 非空输入的工作量均为正整数，hours 为非负整数。
    if not workloads:
        return 0
    if hours < len(workloads):
        return -1
    left, right = 1, max(workloads)
    while left < right:
        mid = left + (right - left) // 2
        required = sum((work + mid - 1) // mid for work in workloads)
        if required <= hours:
            right = mid
        else:
            left = mid + 1
    return left
```

这里候选速度范围是闭区间 `[left,right]`，并保证 right 可行：速度达到最大工作量时，每项都只需一小时。如果小时数比项目数还少，任何速度都做不完，提前返回 −1。整数向上取整 `(work + v - 1) // v` 适用于这里的正整数；固定宽度语言还需保证加法和累计小时数不会溢出。

设最大工作量为 M，每轮判断扫描 n 项，最坏时间 O(n log(M + 1))，额外空间 O(1)。如果改成“每小时可以混合处理不同项目”，当前小时数公式就不再对应题意，代码即使没有边界错误也会算错。二分的可行性检查必须保留原问题的约束。

## 哪些目标不适合直接二分

“速度恰好让用时等于 8”不保证呈现假到真的单次变化：低速为假，中间为真，更高速又可能为假。通常应该先找“用时不超过 8”的最小速度，再检查额外条件。寻找某个无序数组的峰值则有另一套局部排除证明，不能把它误说成整个数组单调。

已经有标准库时可使用 Python 的 `bisect_left`、`bisect_right`，或对应语言的边界查找函数，但仍要知道返回的是插入位置。二分只减少比较次数；若数据结构不能常数时间访问中间元素，还需计算访问或移动迭代器的成本。

## 给分界线写测试

lower bound 的结果 p 应同时满足两件事：所有小于 p 的有效下标都对应小于目标的值，所有大于等于 p 的有效下标都对应大于等于目标的值。测试这个性质比只检查某个示例返回 3 更全面。可以生成很短的数组，排序后遍历不同目标，与从左向右找第一个符合条件位置的结果比较。

对答案二分的结果 v，应验证 v 可行，而且 v − 1 不可行，后者只在 v 大于最低候选值时检查。只验证返回速度能完成工作不够：速度取最大值几乎总可行，却未必最小。前面的 `[3,6,7,11]` 既要验证 4 在 8 小时内完成，也要验证 3 需要超过 8 小时。

若可行性函数很复杂，可以先单独用几个候选值验证它，再接入二分。把速度固定后，程序只是在模拟小时数，不涉及查找边界；这能把“判断函数算错”和“区间更新算错”分开检查。浮点答案则不能照搬整数的 `mid + 1`，通常按误差或固定迭代次数结束，并说明误差标准是绝对误差还是相对误差。

固定宽度语言还要检查中点计算。`(left + right) / 2` 可能在相加时溢出；非负且有序的边界可写成 `left + (right - left) / 2`。这只能解决中点的加法问题，不能替可行性判断中的总和、乘积提供溢出保护，它们仍需逐项检查。
