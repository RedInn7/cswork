# 排行榜服务

做一个游戏或竞赛用的排行榜服务：提交分数，查前 N 名、查某人的名次、查名次附近的人。一个服务托管多个榜单，互不影响。语言和框架不限。

## 接口

请求和响应都是 JSON。榜单名和玩家名只含字母、数字、`_` 和 `-`，长度 1–32。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/boards/{board}/scores` | 请求体 `{"player": 名字, "score": 0 到 10^12 的整数}`。只保留每个玩家的最高分。返回 200 `{"player", "score", "rank"}`，是提交后的最高分和名次。榜单第一次提交时自动创建。 |
| `GET` | `/boards/{board}/top?limit=10&offset=0` | `{"total": 玩家数, "items": [{"player", "score", "rank"}, …]}`。limit 1–100，默认 10；offset 默认 0。 |
| `GET` | `/boards/{board}/players/{player}` | 该玩家的 `{"player", "score", "rank"}`。 |
| `GET` | `/boards/{board}/players/{player}/around?radius=2` | 按排序位置取该玩家前后各 radius 个（0–50，默认 2），到头就截断。 |
| `DELETE` | `/boards/{board}/players/{player}` | 删除该玩家，返回 204。 |

排序：分数从高到低，同分按名字的字节序升序。名次：1 加上分数严格更高的人数，所以同分同名次，下一个名次会跳过（1、2、2、4）。

错误：不存在的玩家返回 404；请求体不合法、limit 或 radius 越界返回 400。

## 约束

- 查名次和取前 N 名不能每次都把全榜排序一遍。写下各个操作的时间复杂度。
- 同一玩家的并发提交不能丢分：最后留下的必须是最高的那个。
- 内存实现即可。

## 加分项

- 用 Redis 的有序集合（ZADD、ZREVRANK、ZREVRANGE）实现一个版本，和你自己的数据结构比一比。
- 按周的榜单：每周一 00:00 UTC 自动换新榜，旧榜可查。
- 十万玩家、每秒一千次提交的压测，给出 p99。
- 防作弊的思路：分数从哪来，怎么校验。
