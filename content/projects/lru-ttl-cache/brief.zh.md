# 带 TTL 的 LRU 缓存服务

做一个能通过 HTTP 访问的内存缓存：按条数限容量，满了淘汰最久没用的；每个值可以带过期时间。值是任意字节。语言和框架不限，但 LRU 结构请自己写，不要直接用语言自带的 LRU 容器。

## 接口

key 只含字母、数字和 `_ . : -`，长度 1–128。容量（条数）由启动参数或环境变量 `CAPACITY` 决定，默认 100。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `PUT` | `/cache/{key}?ttl_ms=N` | 请求体就是值（原样字节，最大 1 MiB）。`ttl_ms` 可选，正整数，表示多少毫秒后过期；不带就不过期。覆盖已有的 key 时，值和过期时间一起替换。返回 204。 |
| `GET` | `/cache/{key}` | 命中返回 200 和原样字节；不存在或已过期返回 404。命中会让这个 key 变成「最近使用」。 |
| `DELETE` | `/cache/{key}` | 删除返回 204；不存在返回 404。 |
| `GET` | `/stats` | `{"hits", "misses", "evictions", "size", "capacity"}`，计数从启动时开始。 |

规则：

- 每次 `GET /cache/...` 记一次命中或未命中。
- `size` 只算没过期的 key。
- 写入一个新 key 时如果已满：先丢掉已经过期的；还是满的，才淘汰最久没用的那个，并给 `evictions` 加 1。丢掉过期的不算淘汰。
- 值超过 1 MiB 返回 413（直接关闭连接也可以），不能存进去；`ttl_ms` 不是正整数返回 400。

## 约束

- GET、PUT、DELETE 都要 O(1)（均摊）：哈希表加双向链表。
- 多个客户端同时读写不能出错。

## 加分项

- 后台定期清理过期 key，说明它和「访问时才检查」各自的代价。
- 按字节而不是按条数限容量。
- 对比 LRU、LFU、W-TinyLFU 在一段真实访问日志上的命中率。
- 加一致性哈希，把多个节点组成一个缓存集群。
