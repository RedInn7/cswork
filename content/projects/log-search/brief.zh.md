# 日志检索服务（倒排索引）

做一个小型的日志检索服务：批量写入结构化日志，按关键词、短语、级别、服务和时间范围检索，结果按时间倒序分页。核心是自己实现倒排索引，不用 Elasticsearch、Lucene 或数据库的全文检索。语言和框架不限。

## 接口

**写入** `POST /logs`：请求体是 NDJSON，每行一个 `{"ts": 毫秒时间戳（≥ 0 的整数）, "level": "debug|info|warn|error", "service": 1–64 个字符, "msg": 字符串}`，不能有别的字段，空行忽略。返回 200 `{"ingested": 行数}`。只要有一行不合法，整批都不写入，返回 400 `{"error", "line": 第几行（从 1 开始）}`。

**检索** `GET /search`，参数都可选：

| 参数 | 含义 |
| --- | --- |
| `q` | 空格分隔的检索词，必须全部命中。双引号括起来的是短语。 |
| `level` | 最低级别：`warn` 返回 warn 和 error。 |
| `service` | 服务名完全相等。 |
| `from`、`to` | 时间范围 `from ≤ ts < to`。 |
| `limit` | 每页条数，1–500，默认 50。 |
| `cursor` | 上一页返回的 `next`。 |

返回 `{"total": 命中总数, "items": [{"id", "ts", "level", "service", "msg"}], "next": 下一页的 cursor，没有就是 null}`。排序：`ts` 从新到旧，同一 `ts` 后写入的在前。

分词规则（写入和检索用同一套）：转成小写，按「不是 a–z、0–9 的字符」切开，比如 `Host-3 (code=503)` 得到 `host`、`3`、`code`、`503`。一个检索词切出不止一个词元（比如 `host-3`）时按短语处理。短语要求这些词元在消息里连续出现。只匹配完整词元，`tim` 不会命中 `timeout`。

参数不合法（limit 越界、未知级别、from 不是数字）返回 400。

## 约束

- 必须用倒排索引：词元到日志 ID 列表，多个词时求交集，从最短的列表开始。不能每次检索都扫一遍全部日志。
- cursor 分页在两次请求之间有新日志写入时也不能重复或漏掉旧结果。
