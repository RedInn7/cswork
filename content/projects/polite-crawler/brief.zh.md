# 遵守 robots 并限速的爬虫

写一个命令行爬虫：从一个起始网址出发，只在同一个站点内按广度优先抓页面。它必须「有礼貌」：先读 robots.txt 并遵守，两次请求之间留出间隔，服务器说太忙时按 `Retry-After` 等一会儿再试。语言不限。

## 用法

```
你的程序 起始网址 --max-pages N --delay-ms D
```

每抓完一个页面，往标准输出打印一行 JSON：`{"url": 页面网址, "status": 最终的 HTTP 状态码, "depth": 离起始页的链接距离}`。起始页的 depth 是 0。抓完或达到上限后退出码为 0。其他输出请写到标准错误。

## 规则

- **同站**：只跟随与起始网址同一协议、主机、端口的 `http`/`https` 链接；`mailto:`、`javascript:` 和外站链接一律不请求。
- **robots.txt**：任何页面之前先请求 `/robots.txt`。所有请求的 `User-Agent` 都要包含 `cswork-bot`。如果有 `User-agent: cswork-bot` 的组，就只用这一组，否则用 `*` 组；按其中的 `Allow` 和 `Disallow` 决定能不能抓。robots.txt 不存在（404）时全部允许。
- **去重**：相对链接要解析成绝对网址，去掉 `#` 后面的片段；查询参数不同算不同的网址。同一个网址只请求一次。
- **只解析 HTML**：只有 `Content-Type` 是 `text/html` 的页面才从里面找 `<a href>`。其他类型的文件也算抓了一页，但不解析。
- **限速**：任意两次请求（包括 robots.txt 和重试）之间至少间隔 `--delay-ms` 毫秒。
- **重试**：遇到 429 或 503 时，等待 `Retry-After` 秒（没有就等 1 秒）后重试同一个网址，最多一共试 3 次。打印的 status 是最后一次的结果。其他错误码（比如 404）不重试，照样打印。
- **上限**：`--max-pages` 是最多抓多少个页面（不含 robots.txt），按广度优先的顺序。

## 约束

- 不要一次把整个站的链接都抓下来再过滤，robots 和同站检查要在请求之前做。
- 想并发的话，同一个站点仍然要满足间隔要求。

## 加分项

- 支持 `Crawl-delay`，和 `--delay-ms` 取较大的那个。
- 断点续爬：把待抓队列和已抓集合存盘，重启后接着抓。
- 多站点并发：每个站点一个独立的限速器。
- 按 `sitemap.xml` 发现页面，按 `Last-Modified` 做增量抓取。
