# 零、偶、奇

三个线程共用一个 `ZeroEvenOdd` 对象，分别调用 `zero(emit)`、`even(emit)` 和 `odd(emit)`。三个方法合起来，要让 `emit` 按这个顺序收到 2n 个数：

0 1 0 2 0 3 … 0 n

也就是每个正整数前面都先输出一个 0。`zero` 负责所有的 0，`odd` 负责奇数 1, 3, 5, …，`even` 负责偶数 2, 4, 6, …。每个方法只能在轮到自己时调用 `emit`。

| 方法 | 作用 |
| --- | --- |
| `ZeroEvenOdd(n)` | 要输出的最大正整数 |
| `zero(emit)` | 调用 n 次 emit(0)，每个正整数之前一次 |
| `even(emit)` | 按顺序 emit 不超过 n 的每个偶数 |
| `odd(emit)` | 按顺序 emit 不超过 n 的每个奇数 |

驱动会测很多轮，每轮新建对象，随机打乱三个线程的启动顺序，并在 `emit` 前后随机让出 CPU 或短暂休眠。不要用 `sleep` 或空转循环等待。判题只比较输出，所以绕开线程直接拼出答案也能通过，但那样就没有练到并发。

## 输入

第一行是随机种子 seed 和轮数 R。接下来 R 行，每行一个 n。

1 ≤ R ≤ 100，1 ≤ n ≤ 50，0 ≤ seed < 2^31。

## 输出

每轮输出一行：这一轮 emit 按调用先后收到的数，以空格分隔。

## 样例说明

第一轮 n = 2，正确的顺序是 0 1 0 2。第三轮 n = 1，even 没有要输出的数，应该直接返回；这一行是 0 1。

## 提示

- 用三个信号量表示“轮到谁”：zero 的初值为 1，另外两个为 0。zero 每输出一个 0，就根据下一个数的奇偶唤醒 odd 或 even；它们输出后再把执行权还给 zero。
- 每个方法事先就知道自己要循环几次，不需要额外的“结束”信号。
- 用一个条件变量也行：共享一个“下一个该输出什么”的变量，每个线程等到它等于自己要输出的值。
