# LRU 缓存

实现容量为 capacity 的 LRU（最近最少使用）缓存 `LRUCache`。每次 `get` 命中或 `put` 一个键，这个键都变成「最近使用」；新键放不下时，淘汰最久没被使用的那个键。

要求 `get` 和 `put` 都是 O(1)：用哈希表从键找到节点，再用一条**自己写的双向链表**按使用时间串起所有节点（表头最近、表尾最久），移动、删除节点都只改指针。可以用语言自带的哈希表（`dict`、`unordered_map`、`HashMap`、Go 的 `map`），但不能用自带顺序的容器（`OrderedDict`、`LinkedHashMap`）。

需要实现的方法：

| 方法 | 作用 |
| --- | --- |
| `get(key)` | 返回值并把键标记为最近使用；键不存在返回 -1 |
| `put(key, value)` | 写入或更新，并标记为最近使用；如果因此超出容量，淘汰最久未使用的键并返回它，否则返回 -1 |
| `keys()` | 从最近到最久列出所有键，供驱动打印 |

## 输入

第一行是容量 capacity 和操作数 q。接下来 q 行，每行一个操作：

get k / put k v / order

1 ≤ capacity ≤ 10^4，1 ≤ q ≤ 2×10^4，0 ≤ k, v ≤ 10^9。order 输出的键总数不超过 5×10^4。

## 输出

`get` 输出值或 -1；`put` 输出被淘汰的键，没有淘汰输出 -1；`order` 在一行内从最近到最久输出所有键（以空格分隔），缓存为空时输出 empty。

## 样例说明

容量为 2。put 1 和 put 2 之后顺序是 2 1。get 1 命中，1 变成最近，顺序是 1 2。put 3 放不下，淘汰最久的 2。get 2 得到 -1。put 1 10 只是更新 1 的值并把它移到最前，不淘汰。put 4 淘汰此时最久的 3。

## 提示

- 在链表两端各放一个哨兵节点，插入和删除就不用判断「前面或后面是不是空的」。
- 更新已存在的键不会改变缓存大小，不应该淘汰任何键。
- 淘汰时要同时从链表和哈希表里删掉这个键，所以节点里也要存键。
