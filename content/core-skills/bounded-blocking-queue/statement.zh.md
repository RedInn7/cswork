# 有界阻塞队列

实现一个容量为 capacity 的先进先出队列 `BoundedBlockingQueue`，供多个生产者线程和多个消费者线程同时使用：

- `put(x)`：队列已满时阻塞等待，直到有空位，再把 x 放到队尾。
- `take()`：队列为空时阻塞等待，直到有元素，再取出并返回队头。
- 任何时刻队列里的元素都不能超过 capacity 个；元素按放入的先后顺序被取出，不丢失、不重复。

请用锁加条件变量（或信号量）自己实现，不要直接用语言自带的阻塞队列：Python 的 `queue.Queue`、Java 的 `ArrayBlockingQueue` 等 `BlockingQueue`、Go 的带缓冲 channel 都不行。普通的 `deque`、数组、切片可以用来存元素。等待时不要用 `sleep` 或空转循环。

| 方法 | 作用 |
| --- | --- |
| `BoundedBlockingQueue(capacity)` | 最多容纳的元素个数 |
| `put(x)` | 满时等待，然后放到队尾 |
| `take()` | 空时等待，然后取出并返回队头 |

每轮有若干生产者和消费者线程，启动顺序随机。驱动在调用前后随机让出 CPU 或短暂休眠，有的消费者还会故意晚一点开始，让队列被填满。驱动自己统计放入和取出的情况，一旦发现问题就立即报告。判题只比较输出，所以绕开线程直接拼出答案也能通过，但那样就没有练到并发。

## 输入

第一行是随机种子 seed 和轮数 R。接下来 R 行，每行四个数 capacity、P、C、k：这一轮有 P 个生产者、C 个消费者，生产者 i（从 0 开始）依次放入 i·k + 1 到 i·k + k 这 k 个数。P·k 个数由 C 个消费者分着取完，每个消费者取的个数事先定好。

1 ≤ R ≤ 100，1 ≤ capacity ≤ 5，1 ≤ P, C ≤ 3，1 ≤ k ≤ 60，0 ≤ seed < 2^31。

## 输出

每轮全部数取完时，输出一行两个数：取出的元素个数 P·k，以及取出的所有数之和。

驱动一旦发现问题，就在已经输出的行后面再输出一行 round k: 加上问题描述，然后立即结束。问题包括：the queue went over its capacity of c（队列里超过了 c 个元素）、take() returned x, which was never put（取出了没放过的值）、x was taken twice（同一个数被取了两次）、x came out after y, though it was put first（同一个生产者的数没按顺序取出）、only a of b items came out（有数没被取出）。

## 样例说明

第二轮容量为 1，两个生产者分别放入 1 2 3 和 4 5 6，两个消费者各取 3 个。容量为 1 意味着每次 put 都要等上一个元素被取走。6 个数全部取出，和为 21，输出 6 21。

## 提示

- 一把锁加两个条件变量：not_full 给生产者等，not_empty 给消费者等。put 之后唤醒一个消费者，take 之后唤醒一个生产者。
- 等待一定要写在 while 循环里：被唤醒时，条件可能已经被别的线程抢先改掉了。
- 信号量写法：slots 初值为 capacity，items 初值为 0，另用一把锁保护队列本身；先拿信号量，再拿锁，顺序反了会死锁。
