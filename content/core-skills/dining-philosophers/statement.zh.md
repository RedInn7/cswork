# 哲学家就餐

n 位哲学家围坐在圆桌旁，编号 0 到 n - 1。每两位相邻的哲学家之间放着一把叉子，共 n 把：叉子 p 在哲学家 p 和哲学家 (p + 1) % n 之间。所以哲学家 p 只能用叉子 p 和叉子 (p + 1) % n，吃饭时两把都要拿在手里。

每位哲学家是一个线程，会多次调用 `dine(p, pick, eat, drop)`。每次调用里你要：用 `pick(f)` 拿起自己的两把叉子，调用一次 `eat()`，再用 `drop(f)` 放下这两把叉子。请保证：

- 同一把叉子同一时刻只在一位哲学家手里：别人拿着时不能 `pick`。
- `eat()` 时手里要有自己的两把叉子；`dine` 返回前两把叉子都要放下。
- 不能死锁：所有哲学家都要吃完自己的份。比如每人都先拿左手边的叉子，就可能人人拿着一把、等着另一把。

| 方法 | 作用 |
| --- | --- |
| `DiningTable(n)` | 哲学家和叉子的数量 |
| `dine(p, pick, eat, drop)` | 哲学家 p 吃一次：pick 两把叉子，eat 一次，drop 两把叉子 |

`pick`、`eat`、`drop` 是驱动的记录函数，本身不会阻塞，互斥要靠你自己的锁来保证：通常是先拿到叉子 f 对应的锁，再调用 `pick(f)`，`drop(f)` 之后再释放这把锁。驱动会随机打乱线程启动顺序，并在这些调用前后随机让出 CPU 或短暂休眠。判题只比较输出，所以绕开线程直接拼出答案也能通过，但那样就没有练到并发。

## 输入

第一行是随机种子 seed 和轮数 R。接下来 R 行，每行先是 n，再是 n 个数：哲学家 0 到 n - 1 这一轮各要调用几次 dine。

1 ≤ R ≤ 100，2 ≤ n ≤ 7，每人 0 到 8 次，0 ≤ seed < 2^31。

## 输出

每轮全部哲学家吃完时，输出一行：每位哲学家实际吃的次数，以空格分隔。

驱动一旦发现问题，就在已经输出的行后面再输出一行 round k: 加上问题描述，然后立即结束。比如 philosopher 2 picked up fork 3 while philosopher 3 held it（拿了别人手里的叉子）、philosopher 1 ate without holding forks 1 and 2（没拿齐叉子就吃）、philosopher 0 left the table holding a fork（dine 返回时还拿着叉子）、philosopher 4 ate 0 times in one dine call（一次 dine 没有恰好吃一次）。

## 样例说明

第一轮 5 位哲学家各吃一次，输出 1 1 1 1 1。第三轮哲学家 0 一次也不调用 dine；哲学家 1 和 2 共用叉子 2，不能同时吃，输出 0 2 1。

## 提示

- 给每把叉子一把锁。打破“循环等待”最简单的办法是规定顺序：每个人都先拿编号小的那把叉子。
- 另一种办法是用一个初值为 n - 1 的信号量，最多允许 n - 1 个人同时去拿叉子，这样总有人能拿齐。
- 一把全局锁也能保证正确，但同一时刻只有一个人在吃。
