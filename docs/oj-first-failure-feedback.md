# OJ 首错反馈

正式提交按测试点顺序评测，遇到第一个答案错误或运行资源错误立即确定失败。只有全部测试点通过才显示“通过”。普通样例运行仍保留逐样例反馈，不把第一个样例通过误当作整题通过。

## 用户能看到什么

- 排队、编译、正在评测，以及已完成/已通过的测试点数量。
- 正式提交失败后优先展示首个失败用例的输入、预期输出、实际输出和错误信息。
- 后续没有评测的用例显示“未运行”，不是失败或通过。
- 每个错误详情字段最多 32 KiB；截断有明确提示。超大用例不能据此保证完整复制重现。

只有提交本人和老师可以读取失败详情。原有 `cases` 数组仍不暴露隐藏用例；额外 `firstFailure` 只返回这次正式提交实际失败的一个用例，不返回剩余隐藏测试。旧的隐藏结果未保留输出时不伪造详情。

## 执行与兼容

失败结果与终态一起持久化，前端可立即读到；已启动的相邻测试使用独立执行取消信号终止，不把答案错误误标成用户取消。停止继续调度后续测试，等待已启动执行完成取消清理，再释放编译文件和 worker 槽。

这项修改减少错误提交的等待和评测资源占用，不减少正确解必须通过的测试点，也不解决提交开始前的队列容量瓶颈。多个正确解同时提交仍可能排队。

参考 LeetCode 的失败用例反馈体验（[官方说明](https://support.leetcode.com/hc/en-us/articles/360011834174-I-encountered-Wrong-Answer-Runtime-Error-for-a-specific-test-case-When-I-test-my-code-using-this-test-case-it-produced-the-correct-output-Why)）。这里仍保留 CSWork 每测试点独立沙箱，不复制其同一程序实例执行全部测试的内部方式，也不声称两站性能完全相同。
