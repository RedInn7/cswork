# 备份完整性与恢复

`scripts/backup.mjs` 使用独立只读连接制作 SQLite 在线快照，然后从快照读取附件清单。每个附件先保留到本轮私有临时目录，并校验文件类型和大小；同文件系统使用硬链接，跨文件系统使用独占复制。归档只包含这份固定清单，因此学员同时删除原附件不会让已保留的文件消失，新上传且未进入快照的文件也不会混入归档。

如果引用文件在保留前已被删除，或上传尚未完成，脚本会失败并删除本轮半成品，保留以前的完整备份。等待在途上传完成后可重新执行；不要把一次失败当成成功备份。普通文件复制和归档前会检查空间，保留至少 3 GiB 磁盘余量。

成功结果使用同一时间戳，包括：

- `cswork-<时间>.sqlite`：数据库快照。
- `cswork-<时间>-attachments.tar.gz`：该快照的附件文件。
- `cswork-<时间>-media.json`：该快照引用的媒体清单；文件位于共享的 `media-objects/`。
- `cswork-<时间>-complete.json`：最后写入的完成标记，包含前三项文件名和数量。

从本次升级之后的备份恢复时，先检查完成标记能够解析且列出的三个文件都存在。停止 cswork 应用和 OJ worker，保留当前数据副本；恢复同一时间戳的 SQLite 与附件归档，再将媒体清单对应的 `media-objects` 文件恢复到 `MEDIA_PATH`。数据库与附件归属 `cswork:cswork`，媒体归属 `cswork:www-data`、权限 `0640`。核对 SQLite 完整性、附件数量和媒体大小后，再启动服务。

备份目录中的 `.backup.lock` 只协调备份进程，不阻塞学员上传请求。若进程被强制终止或主机重启，先确认锁中记录的备份进程已经结束，再删除遗留锁和 `.backup-pending-*` 临时目录。没有完成标记的本轮输出不能用于恢复；已有完整备份不应删除。成功备份后保留最近 14 天的快照与归档，媒体对象继续保留，避免破坏其他快照的引用。

媒体导入后的服务用户归属验证见 [视频导入说明](IMPORT-GOMALL-VIDEOS.md)。同机备份用于误删和发布回滚，异地备份应一起复制完成标记、对应的三个文件及媒体对象。
