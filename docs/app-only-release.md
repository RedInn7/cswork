# 一键发布

日常上线用 `deploy/release.sh`，在本机执行一条命令：

```bash
ssh ubuntu@<服务器> 'bash -s -- main' < deploy/release.sh
```

第二个参数可选，是发布 OA 题时使用的教师邮箱；不传就取服务器 `/etc/cswork/cswork.env` 中 `ADMIN_EMAILS` 的第一个。第一个参数也可以是完整提交 SHA。

脚本依次执行：

1. 检查目标提交在 GitHub 上的全部 CI 检查是否已成功完成；没跑完或有失败就停止。
2. 在 `/srv/cswork/builds/<sha>` 克隆并构建，使用与线上相同的 Node 版本。目录对 cswork 用户可读，不需要临时改权限。可用空间不足 8 GiB 时直接停止。
3. 如果 `drizzle/` 或 `db/` 有改动，停止并提示改用 `deploy/install.sh`。
4. 调用下面的 `app-only-release.sh` 部署，失败会自动回滚。
5. 找出所有还没发布的已验证 OA 批次，逐批运行 `publish-oa-judge.ts`，发布完复查一遍。
6. 确认站点正常响应后删除构建目录。

脚本可以重复运行：目标版本已经部署时只做发布这一步。发布后的草稿不再保存题包副本。

# 仅更新应用代码（底层脚本）

`deploy/app-only-release.sh` 用于本次 OA 题库上线：保留数据库、环境变量、systemd 配置、Nginx、语言服务和评测容器，不迁移、不备份数据库。不能替代常规数据库迁移部署。

调用前必须由发布者核对旧版本到候选版本的完整 Git diff，确认数据库 schema、迁移、启动时数据库操作、评测任务/草稿格式和现有运行配置均兼容。候选构建必须来自该候选提交，并已通过测试、类型检查、生产构建和真实 HTTP 检查。脚本不会自行证明 Git diff 或构建的来源。

```bash
sudo bash deploy/app-only-release.sh \
  <当前部署的完整SHA> <候选完整SHA> \
  /home/ubuntu/cswork-build/<已验证的构建目录> /opt/cswork/runtime/node
```

脚本要求线上 Web 和 worker 已启动、队列未暂停、目标版本目录不存在，并预留至少 512 MiB 磁盘空间。复制完整应用和私有 OA 目录后，暂停队列并等待正在评测的提交结束；排空失败只恢复队列，不停止 worker。之后原子切换版本，重启 Web/worker，检查首页数据及本次启动后的健康心跳。成功后恢复队列，旧版本完整保留。

失败会回切旧版本并检查健康；回滚无法确认健康时维持队列暂停并报错，需要人工处理。正常运行中的程序仍可能写入业务数据和 worker 心跳；“不改数据库”指不执行部署迁移或直接修改数据，并非停止全部业务写入。不要并行运行其他部署工具；锁仅防止该脚本自身重复执行。

部署后核对新版本 `REVISION`、登录后 OA 列表/题解、匿名访问拒绝及私有目录 404，再检查原有算法题单和评测队列。脚本失败或中断留下的候选版本目录保留供排查，不自动删除任何发布目录。
